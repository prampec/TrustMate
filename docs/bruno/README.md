# TrustMate Bruno field-test collection

A [Bruno](https://www.usebruno.com/) API collection exercising every
route in `internal/api/router.go` end to end against a running TrustMate
instance, run via the `bru` CLI. It's the tool behind
[`docs/field-test-report.md`](../field-test-report.md) — that report is
generated by running this collection and folding the results into prose.

## Layout

```
bruno.json              collection config: mTLS client cert, templated by env vars
environments/sandbox.bru baseUrl, certDomain, certFile/certKeyFile, intermediateSerial
fixtures/               static, non-sensitive request bodies (CSRs are NOT here -- see below)
generated/               gitignored -- CSRs/keys/DER fixtures produced at run time
scripts/run-all.sh      orchestrates the whole collection in the right order
01-health/               healthz, readyz, metrics
02-ca-distribution/     root/intermediate CA cert download
03-profiles/            list/reload certificate profiles
04-clients/             issue/list API client certs (RBAC onboarding)
05-certificates/         issue/get/revoke leaf certs + every documented error case
06-audit/               audit trail
07-revocation/          CRL + OCSP (good/revoked/unknown/malformed)
08-tsa/                 RFC 3161 timestamping, all hash algos, rotation
09-acme/                 RFC 8555 routes (expect 404 unless TRUSTMATE_ENABLE_ACME=true)
10-auth/                mTLS/RBAC boundary proof: no-cert, manager-allowed, manager-forbidden
```

## Why some fixtures are generated, not committed

Most binary/CSR-bearing requests in this collection depend on server state
that doesn't exist until you've already run part of the collection:

- **CSRs** (`document-signing.csr`, `revoke-me.csr`, `manager-client.csr`)
  need a fresh keypair each run so a real, matching private key is
  available afterward (needed for the RBAC demo in `10-auth/`, which
  authenticates *as* the manager client `04-clients/add-client.bru` just
  minted). They're generated into `generated/` by `scripts/run-all.sh` and
  never committed.
- **OCSP "good"/"revoked" DER requests** need the *actual issued serial*
  of a cert minted moments earlier in the same run — there's no way to
  pre-bake these. `scripts/run-all.sh` extracts the issued PEM from the
  certificate-issuance response, builds the DER request with `openssl
  ocsp`, and only then runs `07-revocation`.

What *is* committed under `fixtures/`: the RFC 3161 timestamp-query DER
files (independent of any issued cert -- just a document hash) and one
OCSP request for a fabricated, never-issued serial (`ocsp-req-unknown.der`,
built against the sandbox's stable `work/intermediate.pem` issuer
identity) -- these don't depend on anything generated at run time.

## Running it

Requires `bru` (Bruno CLI v4+), `openssl`, and `python3`. From the repo
root:

```sh
docs/bruno/scripts/run-all.sh                          # defaults to https://test.me:8182
docs/bruno/scripts/run-all.sh https://your-host:8443   # point at any live instance
```

This runs all 43 requests across four phases (main pass → derive OCSP
fixtures → revocation pass → RBAC boundary demo) and prints a pass/fail
summary per folder. See `scripts/run-all.sh`'s header comment for exactly
what each phase does and why the split is necessary.

### Running one request by hand

```sh
cd docs/bruno
bru run 01-health/healthz.bru --env sandbox \
  --env-var baseUrl=https://your-host:8443 \
  --env-var certDomain=your-host \
  --cacert ../../work/root.pem
```

`certDomain` must be a substring of the host you're hitting — it's how
`bruno.json`'s `clientCertificates` block (templated, see below) decides
whether to attach the mTLS identity to a given request. `--cacert` points
`bru` at this deployment's root CA so TLS verification succeeds without
`--insecure` (mirrors `openssl verify -CAfile work/root.pem` in the
original curl-based field test).

### Authentication

Every route except the public PKI ones needs an mTLS client certificate.
`bruno.json` declares one `clientCertificates` entry whose domain, cert
and key paths are all `{{templated}}` from environment variables
(`certDomain`, `certFile`, `certKeyFile` — defaults in
`environments/sandbox.bru` point at the bootstrap admin identity,
`work/admin.pem`/`work/admin-key.pem`). This is what lets
`scripts/run-all.sh` swap in a different identity for the `10-auth/`
RBAC demo (`generated/manager-client.pem`) or none at all
(`certDomain=unused.invalid`, which can't match any real host so no cert
is attached) without touching a single request file.

## Notes / known gaps

- **ACME** (`09-acme/`): `TRUSTMATE_ENABLE_ACME=false` on every sandbox
  this collection has been run against so far, so `directory.bru` and
  `eab-token.bru` intentionally have no status assertion — they currently
  get Go's plain-text 404 (module not routed), not the app's JSON error
  envelope. Kept in the collection as ready-made requests for a future
  ACME-enabled deployment. A full `new-account` → `new-order` → `finalize`
  flow needs RFC 8555 JWS request signing, out of scope for a static
  Bruno request body.
- **Root/intermediate key rotation, Vault/PKCS11 keystores, Postgres
  store, HA**: not exercised here — they're deployment-topology choices
  (see `docs/environment.md`), not REST routes; nothing in
  `internal/api/router.go` changes based on which keystore/store driver
  is behind it.
